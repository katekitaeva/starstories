# План: Перенос названий и выдержек в manifest.json и сопоставление похожих кейсов на Шаге 2

## 1. Контекст и цели

1. **Ручной перенос в `manifest.json` (для 2 существующих кейсов)**:
   - В карточки кейсов было добавлено поле `title` (название), которого ранее не было в манифесте для уже сохранённых кейсов.
   - Пользователь готов добавить названия и короткие выдержки вручную прямо в файл `cases/manifest.json` в репозитории `operator-data`.
   - Требуется чёткая спецификация структуры данных и готовый пример для вставки.

2. **Состав короткой выдержки (выжимки) для DeepSeek**:
   - По результатам уточнения определен точный состав данных:
     - **Темы** (`themes`) — категории обращения;
     - **Суть проблемы** (`problem`) — что произошло у клиента;
     - **Вердикт** (`verdict`) — итоговое решение (в пользу клиента / отказ / компромисс);
     - **Что сработало** (`whatWorked`) — конкретные действия оператора, приведшие к урегулированию.

3. **Будущее использование на Шаге 2**:
   - После того как на Шаге 2 определены темы текущей претензии, система фильтрует `manifest.json` по пересечению тем и готовит компактный блок «Аналогичные кейсы в прошлом».
   - Эта компактная выжимка передаётся в промт DeepSeek, чтобы модель учитывала успешный опыт решения аналогичных споров при формулировании рекомендаций.

## 2. Структура `manifest.json` и инструкция по ручному обновлению

### Где находится файл:
В вашем репозитории `operator-data` по пути: `cases/manifest.json`.

### Рекомендуемая структура элемента кейса в `cases/manifest.json`:
Каждый элемент в массиве `"cases": [...]` должен содержать следующие поля:

```json
{
  "id": "2026-10-07_746899721",
  "file": "2026-10-07_746899721.json",
  "title": "Задержка доставки курьером в праздничный день",
  "date": "2026-10-07",
  "ticket": "746899721",
  "order": "11928374",
  "clientId": "nbvtyqap",
  "themes": [
    "Доставка > Опоздание курьера",
    "Логистика > Задержка отправления"
  ],
  "problem": "Курьер не приехал в согласованный 3-часовой интервал, статус заказа в приложении завис на 'В пути'. Клиент ожидал дома весь день.",
  "verdict": "Решено в пользу клиента",
  "whatWorked": "Согласовали бесплатную утреннюю доставку на следующий день и начислили компенсационный промокод 500 ₽.",
  "digest": "ТЕМЫ: Доставка > Опоздание курьера. ПРОБЛЕМА: Курьер не приехал в интервал, статус завис. ВЕРДИКТ: В пользу клиента. СРАБОТАЛО: Утренняя доставка + промокод 500 ₽."
}
```

### Пошаговая инструкция для ручного редактирования 2 кейсов:
1. Откройте в GitHub ваш репозиторий `operator-data`.
2. Перейдите в папку `cases/` и откройте файл `manifest.json`.
3. Нажмите иконку карандаша (**Edit this file**).
4. Найдите два объекта в массиве `"cases"`:
   - Заполните или добавьте поле `"title": "Понятное название кейса"`.
   - Убедитесь, что заполнены поля `"problem"`, `"verdict"`, `"whatWorked"`, `"themes"`.
   - Добавьте поле `"digest"` (1-3 компактных предложения с ключевыми фактами).
5. Нажмите **Commit changes** (Сохранить изменения).
6. Теперь при открытии кнопки «Загрузить сохранённый кейс» в приложении будут отображаться читаемые названия кейсов, а поиск будет работать по названию, темам и сути проблемы.

## 3. Автоматизация в `process_cases.py` (для всех последующих кейсов)

Чтобы при сохранении новых кейсов через Шаг 5 не приходилось вносить данные в манифест вручную, обновим `OperatorHelp/tools/process_cases.py`:

1. **Извлечение `title`**:
   - Считывание `c.get("title")`.
   - Если заголовок не был заполнен оператором, автогенерация читаемого фолбэка: `Тикет #<ticket>` или `Заказ <order>`.
2. **Формирование поля `digest`**:
   - Автоматическая сборка компактной текстовой выжимки:
     `ТЕМЫ: {themes}. ПРОБЛЕМА: {problem}. ВЕРДИКТ: {verdict}. СРАБОТАЛО: {whatWorked}`.
   - Ограничение длины выжимки до 250-350 символов для экономии контекста DeepSeek.
3. **Нормализация тем**:
   - Приведение объектов `{path, status, note}` к чистым строковым путям `path` для мгновенного поиска по темам.

## 4. Архитектура интеграции на Шаге 2 («Похожие кейсы»)

1. **Загрузка и кеширование манифеста**:
   - Манифест `cases/manifest.json` уже загружается в память при работе со списком кейсов.
2. **Поиск похожих кейсов**:
   - Как только на Шаге 2 выбраны темы (например, `Доставка > Опоздание курьера`), выполняется поиск кейсов из манифеста, имеющих пересечение по темам.
3. **Отображение оператору**:
   - Компактный блок на Шаге 2: «Найдено похожих кейсов: N».
   - Краткий список с названиями и плашкой «Что сработало в прошлый раз».
4. **Передача выжимки в DeepSeek**:
   - В промт Шага 2 (или последующего шага разбора) подставляется блок `<historical_cases>`, содержащий компактные `digest` найденных похожих кейсов.
   - DeepSeek получает готовый ретроспективный контекст без необходимости загружать полные JSON-файлы.
